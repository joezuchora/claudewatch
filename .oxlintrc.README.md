# Lint configuration rationale

`.oxlintrc.json` is JSON and cannot carry comments, so the reasoning for every disabled rule
lives here. A rule may only be disabled with an entry in this file explaining why. Silencing
a rule without a stated reason is a compliance finding under `REVIEW.md` pass 3.

## `no-await-in-loop` — off, repository-wide

`packages/core/src/client.ts` awaits inside its retry loop. That is the intended semantics:
attempts are sequential and separated by a deliberate 2s delay (`SPEC.md §9.3`). The rule's
suggested remedy — collect promises and `Promise.all` them — would fire every attempt
simultaneously and defeat both the retry and the backoff.

## `no-underscore-dangle` — off, repository-wide

`packages/statusline/install/install.ts` writes a `_statusLinePrevious` key when patching
`~/.claude/settings.json`. The leading underscore is part of an external file's key naming,
not a local convention we control.

## `no-new` — off for `**/*.test.ts` only

`packages/vscode/src/statusbar.test.ts` constructs `new StatusBarManager()` to assert on the
constructor's side effects, which is what those tests exist to check. The rule remains
enabled for non-test source, where `new` for side effects is a genuine smell.

## Deliberately still enabled

`no-shadow` currently reports one warning in `packages/vscode/src/commands.ts`, where a local
`const vscode = await import('vscode')` shadows the module-level import. That is a real smell
and is left visible rather than silenced. See `sdlc/001-quality-gate/review.md`.
